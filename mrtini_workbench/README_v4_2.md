# MRTini Workbench 4.2

Extract the complete archive into the repository root, including `workbench.py` and `mrtini_workbench/`. Existing saved runs are not replaced. Restart `python workbench.py` and hard refresh. Existing MRTini v3.1 dynamic GPU engine remains unchanged. The phantom rasterization fix is included. Matplotlib is optional, loaded only when exporting a figure (`python -m pip install matplotlib` if needed).

## Physics

RF diagnostics now distinguish (1) response of an equilibrium spin from retained coefficients, (2) conjugating/refocusing and preserving transverse transfer, (3) individual Fourier transition/component, and (4) independent finite-waveform rotation-only check for generated pulses. The latter integrates the actual generated waveform with the selected voxel's B0 and effective B1 using exact held-field rotations; it omits intra-RF relaxation/diffusion and is **not** the original untruncated native Bloch baker output. Fourier synthesis defaults to one period, 1/|dk|; zero order-only response is constant. Native pulse data for imported sequences is still limited to centre markers/event moments.

Select a contributing water/fat voxel in Acquisition, choose Replay voxel, then inspect the slice evolution in Physics. This replays the same retained graph at a fixed tissue/field column, evaluating the spatial phase at 121 z offsets. Profiles are sampled at up to 64 RF repetitions plus the selected repetition, both after RF in the executor's centre convention and at repetition end. It is not a new fully resolved Bloch calculation of a heterogeneous slice or a continuous trajectory within an RF pulse. No simulation state is changed. The 3D orbit viewer shows z, sampled time and magnetization; k-space 3D shows kx/ky/time (ADC index when actual time is unavailable). Axis scales are independently normalized, with actual ranges displayed. No external JS CDN is needed. Drag to orbit, Shift-drag to pan, scroll to zoom, double-click to reset.

## Sequence designer

Select Design in the navigation. Select a starting recipe or add blocks by clicking/dragging. Click a block to edit its parameters; reorder by dragging or the up/down controls. Set matrix, encoding FOV, slice thickness, TR, shot count (0 = automatic), shot phase advance and phase-encoding order. Validate & preview compiles actual finite RF waveforms, physical gradient moments and nominal ADC trajectory without executing MRTini. Use design & run requires installed native MRTini/CUDA. Recipes are saved/imported as JSON (the generator description, not gammaSTAR). Original presets remain separate and unchanged. Geometry changes do not silently retime existing blocks; reload a template if you want its nominal TE/echo spacing regenerated for the new matrix.

Blocks: finite selective excitation/inversion/refocusing, delays, arbitrary held gradient moments, Cartesian/radial/spiral readouts (automatic nominal prephasing, optional rewinding, phase tracking and alternating polarity). Six templates: FLASH, RARE, SE-EPI, radial GRE, experimental balanced SSFP transient, inversion recovery. Native nominal trajectory is checked against `Sequence.get_kspace()` before numerical execution. Custom recipes assume a shot structure and the existing EXCIT/REFOC primary-coherence convention; no arbitrary nested loops, multi-axis simultaneous block scheduling, multiband, general RF shape import or hardware safety validation. Balanced SSFP has zero nominal centre-to-centre gradient moment for its balanced template, alternating RF phase, and no steady-state preparation guarantee. Non-Cartesian outputs use the existing native reconstruction; no density compensation or scanner-ready gradient claim. No hardware amplitude, slew, SAR or PNS limits are checked.

Independent on-resonance 90 degree rotation and SVG/PDF generation checked. Native CUDA execution of new custom sequences and native RF profile correctness still require local testing. The original presets retain previous behavior. Graph/strip SVG exports remain; actual RF, slice and trajectory SVG/PDF exports are available. Slice heatmaps contain raster colour data and vector axes.
