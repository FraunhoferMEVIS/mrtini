# MRTini Workbench 5.0 — experimental studio release

Install by extracting the ZIP into the repository root (back up your previous workbench first). `python -m pip install -r mrtini_workbench/requirements.txt`; `python workbench.py`. Install `torchkbnufft` if needed, using the same PyTorch environment. Hard-refresh the browser. Existing `runs/` are retained; the archive contains no generated runs. No production Rust/Triton files are replaced.

## Design
The new default Design view uses independent timed RF, Gx/Gy/Gz and ADC events. Drag events, resize their right edges, edit numeric properties, undo/redo, and save/import a flat timed recipe. FLASH and spin echo are simple editable starting points. The previous block composer (RARE/EPI/radial/spiral/bSSFP and IR recipes) is retained as Recipe outline; the editors are separate representations, not losslessly convertible. Physical gradient moments are cycles/m, times ms in the UI. Gradients can overlap RF (with transitions aligned to the RF raster) or ADC; ADC during RF and overlaps on the same channel are rejected. ADC samples are at dwell centres. Timed mode supports explicit shot count, shot-dependent gradient moments and RF phase cycling in the recipe. Backend accepts bounded nested repeat definitions (`channel: repeat`, `start_ms`, `count`, `period_ms`, `events`), but the visual editor only supports flat timed events. The compiler follows the native RF-centre excitation/refocusing convention and checks generated trajectories in native execution. Held gradient lobes are discontinuous; no hardware raster/slew/SAR/PNS compliance or scanner deployment. The displayed scanner B0 is informational: no phantom relaxation or chemical-shift fields are silently changed. Scanner RF/gradient amplitude flags are nominal, not safety certification.

## Acquisition and reconstruction
Phantom, nominal acquisition, and reconstruction matrix now have separate square resolution controls (custom ADC counts allow other sample counts). Preview mode still couples phantom and acquisition; native supports independent phantom sampling. Imported acquisition matrix is defined by the file. Reconstruction laboratory opens a saved signal, and reprocesses without simulating: FFT/NUFFT adjoints, DCF, exact direct adjoint, small exact regularized CG (coil-independent, not SENSE), noise with fixed seed, cosine apodization, point-spread function, and coil selection. The initial reconstruction selector only changes future run defaults. Reprocessed views are temporary, not separate archived acquisitions. Direct CG is bounded to 8 million sample-pixel products. Imported trajectories require explicit units and FOV confirmation. Method/normalization differences disable image error comparisons. Nominal Fourier image coordinates link to nearest phantom voxel only when the convention is known; no registration claimed. DICOM reference remains local, ephemeral and accessible from Experiments; available TR/TE/FA metadata can seed generated built-ins. Export is derived secondary capture, not clinical MR DICOM; complex data remain NPZ. No registration, SENSE, field-aware reconstruction, or persistent DICOM archive.

## Analyze / Experiments
Four top-level views, with RF/magnetization and Pathways nested under Analyze. Existing shared RF/ADC links retained; RF refresh when selection changes. Added Fourier vs independent rotation-only overlay on shared support, sampled-boundary magnetization orbit and 3D retained state-space projection (display subset, species colors). The original untruncated RF baker data and discarded Rust states are not available; this release does not fabricate them. 2D parameter sweeps (max 20 acquisitions) with optional saved-reference relative complex ADC error where trajectories match. Full graph archive remains optional; exact node comparison is not complete path equivalence.

## Limits
Native CUDA, original untruncated Bloch diagnostics, continuous intra-RF magnetization, full visual nesting/groups and multi-select, arbitrary scanner hardware model, arbitrary rectangular built-in matrix, direct measured-image registration, sensitivity-aware inverse reconstruction, real hardware distortion modelling, tolerance-based pathway correspondence, and optimization objectives beyond reference error require further work. Keep the previous version available for scientific work until your installed native Sequence/RF/PDG pipeline has been validated. Tests exercise the native Sequence interface double, preview API and offline browser bridge, not an actual CUDA acquisition.
