# Workbench 5.3: RF context and echo ancestry

Extract at the repository root (replaces Workbench files); restart `python workbench.py` and refresh. No changes to the native simulator, Rust prepass or GPU kernels are required.

- RF response: the local window includes signed slice gradient lobes around the selected finite pulse. Switch to Between adjacent pulses for the full interval. Before/during/after moments are computed from the generated sequence, not an assumed rephaser. The spatial profile shades the prescribed slice; excitation/preparation uses the equilibrium view by default, refocusing uses the transverse-transfer view. The Fourier representation and combined transitions are retained. Imported sequences without a validated finite design retain the existing marker-only limitation.
- Echo contributions: choose a contributing state and RF-history class. The new plot follows a representative strongest predecessor branch (at most 12 RF repetitions) in the retained graph, with actual executor k-space and coherence-time coordinates and actual gradient event endpoints (display decimated above 96 events per repetition). The final point is the selected ADC, not the end of the repetition. Solid teal indicates transverse magnetization, dashed purple longitudinal storage, gold RF transfers. The shaded central sinc lobe is a physical guide, NOT a hard emission gate. The full dephasing factor and ADC kx, ky are also reported. In multi-slice mode the shown rectangular sinc is only a reference.
- The trace chooses locally strongest nonzero incoming class components, honoring species masks and conjugation. It does not assign unique echo identities or imply the full merged class amplitude arose from that particular branch. Contributions remain the complex sum of all retained branches; decay/recovery and temporal coherence are preserved. The readout-only signal chart is optional, below the explanation.
- Trace construction is requested only by the Echo contributions view. The production acquisition is unchanged. Workbench reports exact class contributions and a representative branch, not a fully enumerated exponentially large history tree.

Validation: `python -m pytest -q mrtini_workbench` (run from repository root). Two tests in test_pathway_inspector use the recovered v3.1 prepared CPU engine fixture when available (`test_scaling` and `optimized` on PYTHONPATH); otherwise they skip. They verify ADC coordinates and a controlled F→conjugated Z→F storage/recall with zero final temporal and spatial coherence. The generated FLASH rephaser and RARE gradient moments are tested independently. Native CUDA validation still required.
