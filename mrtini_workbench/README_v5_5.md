# v5.5 — Acquisition-wide RF history overview

In Acquire choose **With diagnostics** and run a native acquisition. Open Analyze → Echo contributions, then choose **Compute overview**. The selected voxel is inherited from Acquire, including its selected physical species. The overview is on demand and does not run during acquisition, including Fast acquisition. Clicking a bar or table row selects the exact RF layer and ADC index for the existing coherence-trajectory inspector. Results are retained in the browser for the current acquisition/voxel until the selection changes; no new simulator run is required to browse them.

The backend discovers contiguous positive `adc_usage` event runs in each actual native repetition, verifies their count against the prepared ADC tensor and uses one midpoint sample per run (the later middle sample for an even count). A window is not an inferred echo or shot: arbitrary readouts, including EPI trains, can have more than one window per RF layer, and RF-only layers still propagate history. A sampling gap splits a window. No sequence names or assumed echo spacing enter this algorithm. The overview is not a full-resolution all-ADC analysis or a whole-phantom decomposition. It is for one selected physical voxel and receiver coil 1, from the retained graph. The underlying RF-history classes are the existing six disjoint categories, not unique physical echo identities. The magnitude-share view normalizes by the sum of category magnitudes; the absolute view stacks magnitudes and marks the magnitude of the actual complex sum. Cancellation is 1 - |complex total| / sum(|component|). Zero-signal rows are shown explicitly.

The diagnostic uses a single pass of history propagation, without storing the whole ancestry or computing spatial profiles. It independently accumulates the unclassified reference and reports the maximum absolute decomposition residual. It leaves the production executor unchanged. Large graphs may still take time to replay and the API holds the native-analysis lock during calculation. Native CUDA validation is outstanding. Offline tests used recovered prepared CPU fixtures and an offline browser API bridge. Optional NUFFT and DICOM tests remain skipped in the test environment.
